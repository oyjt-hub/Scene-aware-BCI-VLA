# 上下文意图模块：实验与消融方案

本方案是尚未执行的实验协议，数字是排期目标，不是现有结果。目标是检验：在相同的场景信息、BCI输入和下游VLA下，小型关系网络能否更准确地形成可执行指令，并在信息不足时提出恰当的澄清。模块输出有限任务语法的英文指令，属于VLA上游的上下文推理模块；本实验不证明VLA内部架构创新。

## 1. 先冻结比较边界

所有方法使用完全相同的公开输入：对象实例、规范化位置、可观测属性/可供性、关系及其置信度、BCI选择与后验、明确告知的当前目标/目的地提示、已经确认的历史。隐藏的任务请求、真实意图标签、未来动作、人工答案和测试集标注不得进入输入。Gemini不额外看原图、长提示里的答案、任务成功日志或更长历史；若另设看原图的VLM方法，必须作为输入不同的独立实验。

固定VLA权重、机器人控制参数、相机、感知输出、候选动作集合、指令模板、最终校验器和用户确认流程。允许的任务仅为 `pick`、`place`、`fold`；现有代码尚不支持的自由任务不进入主比较。所有指令均为待用户确认的建议，确认前不发送机器人命令。

共同校验器会阻止无法消歧、对象不存在或无法用可观测描述唯一指认的提案。因此必须分别报告**原始提案**与**通过共同校验后的结果**。共同校验带来的收益不得写成关系网络本身的能力。

## 2. 主比较与消融

| 方法 | 意图判断 | 语言输出 | 目的 |
|---|---|---|---|
| Rule | 固定、公开的场景/任务规则 | 共同模板 | 检查简单规则是否已足够 |
| Gemini | 冻结版本模型，输出受约束JSON | 共同模板 | 相同信息下比较LLM推理 |
| Full | 关系图编码＋BCI条件查询＋候选评分/状态头 | 共同模板 | 待验证的小型模块 |
| No relations | 去除关系消息与相对几何分支，保留对象xy与自注意力 | 共同模板 | 显式关系/相对几何编码的增益 |
| No BCI query | 关闭网络中的BCI选择/后验条件 | 共同模板 | BCI条件对推理的贡献 |
| No history | 关闭网络中的历史编码 | 共同模板 | 历史对推理的贡献 |
| MLP | 用参数量尽量接近的集合池化MLP替代关系编码 | 共同模板 | 关系架构相对普通小网络的收益 |

消融训练与测试均使用对应变体；每个变体从头训练3个种子，保持训练/验证/测试场景划分一致。不得只在推理时删特征并声称是完整消融。先用同一训练预算，再给MLP相同的验证调参预算，报告参数量、训练轮数、停止规则和耗时。模型容量无法匹配时报告差异。

`No BCI query`移除网络中的离散选择、后验、选择查询与不确定度特征；系统的共同校验器仍读取BCI选择以阻止未授权对象，因此它不是“整个系统不用BCI”。候选枚举必须对各变体相同，且不能预先把所有候选限制为被选对象，否则选择信息会从候选集合泄漏。`No history`保留本次明确给出的goal、confirmed_action和confirmed_destination_id，只移除网络history编码；若这些字段能完全替代历史，必须另列真正需要历史的子集，不能声称历史有效。当前`repeat_last`目标明确表示用户要求沿用上一次已确认动作和目的地，而非系统看到历史就推断用户要重复。共同校验器仍读取历史，故应重点检查raw结果。`No relations`仍有对象xy，且同时去掉相对几何分支，不能单独归因为谓词边或宣称完全无空间信息。

另外做两个离线诊断，不进入机器人现场条件：

- **Oracle感知输入**：在同一测试集用人工纠正的可观测图重复三种主方法，估计感知错误的影响。报告自动感知与人工纠正两套结果，不能混合。
- **澄清策略**：在相同候选意图上比较学习状态头、结构规则和验证集确定的置信度阈值。可以离线绕过某个拒绝规则测量潜在错误释放，但不得把该配置用于机器人。所有实际运行保留共同确认与停止机制。

如果Full和规则相当，结论应是当前受限任务尚未显示学习模块优势。若与Gemini相当且更快，可讨论部署效率，但必须给出质量差异置信区间；“无显著差异”不等于等效。

## 3. 数据、划分与标注预算

两至三周的最低可执行目标：60个真实物理场景，每场景6个上下文条件，共360例。按**物理场景**一次性冻结为32个训练场景（192例）、8个验证场景（48例）、20个测试场景（120例）。这是可行性目标，不是功效分析保证；20个测试场景的区间可能较宽。若达不到该规模，保留独立测试场景并缩小结论，不能把同一场景的重复当成更多独立样本。

一个物理场景包括同一摆放的全部照片、视频相邻帧、增强图、BCI后验变体、改写请求和历史变体，均进入同一分组。相同原始录制或强近重复摆放应进一步合并为一个组；为不同split重新编号不能解决泄漏。训练前保存原始文件清单、内容哈希和split清单。测试锁定后不得用于阈值选择、提示修改、早停、负例筛选或合成训练提示。

至少覆盖以下预先定义的子集，每例可有多个标签，报告每个子集样本数：唯一可判定；多目的地；同类多实例；缺失目的地；动作未知；低BCI置信度；必要历史；感知缺失/冲突。正式测试中的BCI后验尽量来自实际记录。人为构造后验只能称受控扰动；合成JSON只能检验管线。

训练数据必须来自独立真实场景/人工标注，必要时加明确标记的合成增强；主表保留真实测试集结果。未训练权重、随机权重、合成集准确率与模板生成标签均不能作为论文有效性证据。合成训练需要单列“仅真实”与“真实＋合成”比较，避免模型只学生成器规则。

详细标注规则见[ANNOTATION_ZH.md](ANNOTATION_ZH.md)。推荐安排2人各约12–18小时完成首批360例独立标注，再集中裁决；试标20例后重新估算实际耗时。该工时是预算，须由试标校正。

## 4. 离线指标：把推理能力与共同保护分开

主要报告下列计数、比例及配对差异，不将指令字符串相等作为正确标准：

| 维度 | 定义 |
|---|---|
| Ready意图正确率 | 真值为ready的例中，输出ready且动作/源实例/目的实例全部正确的比例 |
| 错误释放率 | 全部测试例中，输出ready但真值为clarify/reject或意图不正确的比例 |
| Coverage | 输出ready的比例；与错误率一起报告，防止“全部澄清”获得虚高安全分数 |
| Selective risk | 已输出ready的例中错误比例；无ready时为不可估计，不能填0 |
| 状态识别 | ready/clarify/reject混淆矩阵、各类召回率及macro-F1 |
| 澄清质量 | 真值clarify例上的澄清召回、slot正确率；另报不必要澄清率 |
| 格式/实例错误 | 非法JSON、非法动作、未知ID、无法唯一指认的语言提案分别计数 |
| 校验器贡献 | raw错误释放与guarded错误释放之差，以及被拦截的正确/错误提案数量 |
| 效率 | 本地推理和总请求耗时的p50/p95，参数量、峰值内存；云请求另报网络/重试、token用量 |

当前评估代码输出的实际字段以JSON为准；本表中尚未自动输出的指标由保存的逐例记录补算并核对分母，不得用一个相近名称代替。拒绝/澄清不得算作机器人成功。错误释放是离线提案属性，不等于实际发生危险动作。

LLM生成温度、模型标识/版本、提示哈希、schema、日期、重试次数和超时固定并记录。缓存原始响应时去除身份凭证；云API失败单列为失败，不以规则猜测覆盖，除非“显式fallback系统”作为单独条件。主表按请求首次评估，重试后的结果另报。若服务不保证完全确定，冻结测试后对同一测试集重复3次API评估，全部保存并按场景分组；不能挑最佳一次。

本地延迟在目标服务器独立进程、相同精度和设备上测量，先预热20次，再对每个测试例至少测一次，报告是否包含特征构建。网络LLM的wall-clock单独展示，不能把GPU内核时间与网络全耗时当成同一测量口径。实际费用由token日志及实验当天官方价计算；本方案不预填费用。

阈值只由验证集确定。报告验证集选择规则、覆盖率和样本数；小验证集上的“错误率低于5%”不能保证总体风险低于5%。若当前模型不能满足预先确定的可接受条件，保持澄清/拒绝并继续离线改进。

## 5. 现场端到端比较

先完成2人的试运行，修复后冻结代码；这2人若见过测试任务，主研究不再计为独立新增参与者。以8–10名参与者为排期目标，3种主方法×2项下游VLA已支持任务×每条件3次重复，共144–180次正式尝试。每人的18次尝试可分两段，提供休息。人数是否足以支持某个差异需按先导方差/成功率做功效评估；预算不足时明确定位可行性研究。

三条件均使用相同BCI、同一VLA、同一确认界面。任务可以从当前系统已成功运行的放置与折叠任务中选择；先验证VLA实际支持，再冻结。设置一部分唯一目标和一部分多实例/多目的地条件，比例预先确定。实验开始前向参与者明确任务目标；只有经协议允许向系统公开的线索进入observation。被隐藏的意图只能用于标注与评价，不能供某一方法额外访问。

采用平衡顺序：8–10人的条件顺序尽量均衡，不宣称满足完整拉丁方；任务摆放在条件间配对并轮换，防止记忆固定位置。VLA具有随机性时固定预先列出的种子并在条件间配对，记录每次实际执行版本。操作者/录像判定者尽量不知道方法标签；参与者无法盲法时如实报告。

一次尝试从任务呈现开始，到完成、停止或预设超时结束。成功由预先定义的物理终态/独立录像判定；**不能由指令正确推算**。所有选择、澄清、确认、LLM超时、失败重试、人工接管、恢复时间均计入原条件。固定最大澄清轮数、超时和人工介入规则，失败不能被“重做一次直到成功”覆盖。

主要现场指标：物理任务完成率、含失败/恢复的总任务时间、BCI选择次数；次要指标：澄清轮数、用户拒绝提案数、人工干预率、按阶段归因的失败以及每条件NASA-TLX。保留疲劳主张时增加预先选定的疲劳量表/测量，NASA-TLX与主动输入占比不能直接等同疲劳。

机器人现场阶段必须沿用现有停机与确认流程，先在不执行动作的回放条件中排除错误指向，再由熟悉设备者执行常规试运行。本包本身不调用机器人接口。

## 6. 统计与预注册

离线独立单位为scene，现场独立单位为participant。离线用场景聚类配对bootstrap给出95%区间：一次抽一个scene并包含它的全部变体，同一次重采样保持方法配对。训练3个种子作为优化不确定性另报均值/范围，不把它们当成3倍数据。必要时同时报告按场景平均与按case汇总的结果，明确权重。

现场先按参与者计算每条件成功率、均值或中位任务时间，再做配对差异与参与者聚类区间；小样本可补配对置换分析。若用混合模型，参与者与场景作为随机因素，但样本不足时不强行拟合复杂模型。不要把8人×18次当作144个独立受试者。提前指定两个主要比较（Full对Rule、Full对Gemini），主要指标和多重比较调整；其他消融/子集标为探索性。

冻结一页实验登记：假设、排除标准、终止规则、指标分母、阈值选择、split、随机种子、模型/API版本和分析脚本哈希。保留失败记录和所有排除理由。若研究涉及新增人体实验，按机构已有批准范围执行；需要新增审批的变更不能由此方案替代。

## 7. 2–3周排期与可交付结果

| 时间 | 交付 |
|---|---|
| 第1–2天 | 试标20例；锁定任务语法、公开信息、失败定义；验证现有VLA任务 |
| 第3–5天 | 真实场景采集与双人标注；冻结split；完成Rule/LLM回放接口 |
| 第6–8天 | Full及4消融训练；只在验证集调参；输出raw/guarded离线记录 |
| 第9–10天 | 冻结权重/提示/阈值；离线盲测与2人现场试跑；冻结后修正须重启相应评估 |
| 第11–15天 | 8–10人正式比较；同步校验日志与录像；保留失败/超时 |
| 第16–18天 | 分组统计、失败归因、复核图表；整理代码/数据版本 |
| 第19–21天 | 写方法、消融、LLM对比与限制；复查每项主张是否有独立证据 |

如果只能两周，优先保证真实独立测试、Rule/LLM/Full比较与三项核心消融（relations、history、MLP）；减少任务种类或参与者内重复，而不混入测试调参。No BCI query保留为离线诊断。现场条件仍只比较三个主方法，不要求把所有消融搬上机器人。
